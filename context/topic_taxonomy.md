## 2. 공통 분류 규칙

**① 대분류는 필수, 중분류는 선택(null 허용)**
- 대분류는 반드시 하나 배정한다.
- 중분류는 근거가 텍스트에 드러날 때만 배정하고, **불명확하면 비워둔다.**
- 이유: 사유가 안 드러나는 경우(주로 *이미 접수한 건의 진행 문의*)에 LLM이 억지 배정하면 데이터가 오염된다.
- 부수 효과: `사유 확인율` 지표가 생긴다. 낮으면 "상담 시 사유를 안 묻고 있다"는 CS 프로세스 신호다.

**② 판정 우선순위 (한 발화에 여러 요소가 섞일 때)**

```
1. 고객의 실제 요청(action)이 무엇인가  →  대분류 결정
2. 그 요청의 사유가 무엇인가            →  중분류 결정
3. 사유가 안 드러나면 중분류 = null
```

**③ 대분류 판별 3축**

| 축 | 질문 | 갈림 |
|---|---|---|
| 1 | 상품을 되돌리려는 요청인가? | 아니오 → A(기다림) / 예 → B·C |
| 2 | 요청 시점에 상품을 받았는가? | 미수령 → **B 취소** / 수령 → **C 반품** |
| 3 | 내 건의 처리인가, 일반 절차 질문인가? | 내 건 → A·B·C / 일반 질문 → **E 절차문의** |

**④ 출력 형식** — 대분류/중분류를 한 번의 호출에서 쌍으로 출력한다. 계층 구조를 프롬프트에 명시한다.

```
{ "major": "C", "minor": "C1" }     또는     { "major": "C", "minor": null }
```

## 3. 대분류 상세

### A. 배송 지연·미도착

**정의:** 주문·결제한 상품의 배송 진행 상황에 대한 문의·불만. 상품을 **기다리는 중**이며 취소·반품 요청은 아니다.

**제외 → 행선지**
- 안 와서 **취소하겠다** → **B2**
- 받았는데 문제가 있어 반품 → **C**
- 배송 정책·비용 일반 문의 → **E1**
- 배송지 변경 → **E3**

| 중분류 | 정의 | 대표 발화 |
|---|---|---|
| **A1** 배송 지연·미도착 | 예정보다 늦거나 도착하지 않음 | "이 주가 지났거든요 그런데 도착을 안 해서" · "십이 일이 넘어가는데 아직도 안 와서요 지금 배송이 왜 안 되는 겁니까" |
| **A2** 배송완료 표시·미수령 | 시스템상 완료인데 실물 미수령 | "배달이 완료되었대요 근데 물건은 집에 안 왔거든요" · "택배 쪽은 배송 완료라고 떠있는데요 아직 못 받았어요" |
| **A3** 배송 조회·일정 확인 | 지연 아님. 위치·예상일 단순 확인 | "주문 결제 후에 배송 기간은 얼마나 소요되나요" · "배송 조회는 어디서 할 수 있어요" |

---

### B. 주문 취소 (배송 전)

**정의:** 상품을 **아직 받지 않은** 상태에서 주문을 무르려는 요청.

**제외 → 행선지**
- 상품 수령 후 되돌림 → **C**
- 취소 방법만 묻는 일반 질문 → **E3**
- 취소했는데 환불이 안 됨 → **C4** (처리지연)

| 중분류 | 정의 | 대표 발화 |
|---|---|---|
| **B1** 단순변심 취소 | 고객 사유의 취소 | "상품을 지금 취소하려는데요 전부다 취소하는 게 아니라 #@상품# 하나만" |
| **B2** 배송지연 사유 취소 | 안 와서 취소 | "오늘도 발송 안 되면 취소 할게요" · "이틀 뒤에 취소해달라고 전화를 했는데 벌써 발송됐다" |
| **B3** 부분출고·품절 취소 | 재고·출고 문제로 인한 취소 | "결제까지 다 했는데 품절이 되었어요 그러면 주문 취소된 거니 환불해 주세요" · "묶음 상품 구매 후 일부만 취소가 가능할까요" |

---

### C. 반품·교환·환불 (배송 후)

**정의:** 상품을 **받은 후** 반품·교환·환불하려는 요청 및 그 처리 상황.

**제외 → 행선지**
- 미수령 상태 취소 → **B**
- 반품·교환 정책·비용 일반 질문 → **E2**
- 제품 고장을 **수리**로 해결하려는 경우 → **I** (아래 §4-② 규칙)

| 중분류 | 정의 | 대표 발화 |
|---|---|---|
| **C1** 제품 하자·불량·파손 | 제품 자체 결함 | "하자상품이 배송되었네요 제품 아래에 고무밴드가 끊어져서 왔네요" · "다 녹아서 왔는데 상한 냄새나요" · "찌그러져서 와서 사진도 올리고" |
| **C2** 오배송·구성품 누락 | 다른 상품·수량 부족 | "반지 세 개 세트인데 링 하나가 없어요" · "#@제품#만 누락되고 다른 제품은 정상 도착했어요" |
| **C3** 단순변심 반품 | 고객 사유(사이즈·색상·마음) | "마음에 안들어서 반품하고 싶은데요" · "본 색상은 네이비인데요 약간 보라색이 섞여있어요" |
| **C4** 반품·환불 처리지연 | 수거·환불이 진행되지 않음 | "반품 수거를 아직 안 해서요" · "엊그제 반품하고 받으셨을 텐데 환불이 안 돼서요" · "회수를 안 해가셔서요" |

---

### D. 상품 주문 접수

**정의:** 전화 등으로 상품을 새로 주문하거나 기존 주문을 추가·변경하는 요청. 상품 스펙·가격 확인이 동반된다.

**제외 → 행선지**
- 결제 수단·오류 → **F**
- 주문한 게 안 옴 → **A1**
- 주문 방법만 묻는 일반 질문 → **E3**

| 중분류 | 정의 | 대표 발화 |
|---|---|---|
| **D1** 신규 상품 주문 | 새 주문 접수 | "#@상품# 구매하려고 합니다 강약 조절되는 건가요" · "퍼팅 연습기구 하나 주문해주세요" |
| **D2** 주문 추가·변경 | 기존 주문에 추가·구성 변경 | "금방 주문했는데요 #@상품#을 추가로 좀 해줬으면 해서" · "혼합구성으로 선택했는데 구성변경이 가능한가요" |

> **참고 (Root Cause 가설 후보):** D가 10.3%로 큰 것은 전화 채널 특성이나, **"온라인에서 주문하기 불편해서 전화한다"는 UX 문제의 역설일 수 있다.** 온라인 문의 데이터에 같은 로직을 적용하면 자연히 축소될 항목이다. Root Cause 단계에서 검토한다.

### E. 절차·정책 문의

**정의:** 내 건의 처리 요청이 아니라 **"어떻게 하나요 / 가능한가요"**를 묻는 절차·정책 질의.

**제외 → 행선지**
- 내 주문·반품의 실제 처리 → **A·B·C**
- 혜택 사용 방법 → **G**
- 계정 관련 방법 → **H**

| 중분류 | 정의 | 대표 발화 |
|---|---|---|
| **E1** 배송 정책·방법 | 배송비·택배사·묶음배송·안심택배 등 | "배송비는 상품별로 각각 적용되나요" · "안심택배 서비스는 뭔가요" |
| **E2** 반품·교환 정책 | 반품 가능 기간·비용·조건 | "무료배송 상품을 교환할 경우 배송비가 얼마인가요" · "교환이나 반품이 불가한 경우는 어떤 것이 있나요" |
| **E3** 주문·결제 절차 | 주문·취소·조회 방법 | "비회원으로 주문했는데 주문 조회는 어떻게 하나요" · "주문한 거 취소하고 싶으면 어떻게 해요" |

> **E는 FAQ·셀프서비스 개선의 1차 소재다.** Recommendation 단계에서 활용한다.

### F. 결제 방법·오류

**정의:** 결제 수단·과정·증빙에 관한 문의와 오류.

**제외 → 행선지**
- 환불 요청 자체 → **C** (결제수단은 조건일 뿐)
- 포인트·쿠폰으로 할인 → **G**

| 중분류 | 정의 | 대표 발화 |
|---|---|---|
| **F1** 결제수단·복합결제 | 카드/현금/무통장/간편결제, 복합결제 | "카드와 현금으로 복합 결제 가능한가요" · "무통장 입금계좌 다시 한 번 보내주시겠어요" |
| **F2** 결제 실패·오류 | 결제가 진행되지 않음 | "결제하려는데 계속 오류가 나요 장바구니에서 결제를 누르면 다음으로 넘어가질 않아요" |
| **F3** 영수증·증빙 | 현금영수증·세금계산서 | "현금 영수증을 발급을 받고 싶거든요" · "지출증빙용 현금영수증은 어디에서 확인 하나요" |

### G. 혜택·적립

**정의:** 쿠폰·포인트·적립금·이벤트·사은품 등 혜택의 사용법·조건·확인.

**제외 → 행선지**
- 가입·계정 행위 중심 → **H** (혜택 내용 중심이면 G)
- 혜택 적용 실패로 결제가 안 됨 → **F2**

| 중분류 | 정의 | 대표 발화 |
|---|---|---|
| **G1** 쿠폰 | 쿠폰 사용·중복적용·유효기간 | "쿠폰이 여러 개가 있는데 동시에 사용 가능한가요" · "한 상품에 여러 쿠폰을 적용할 수도 있나요" |
| **G2** 포인트·적립금 | 적립·사용·소멸·전환 | "포인트가 적립 가능한 한도가 있을까요" · "리뷰를 작성하면 포인트를 주나요" |
| **G3** 이벤트·사은품 | 이벤트 참여·당첨·증정품 | "사은품 안내받고 싶어서요 증정 기준으로 알려주세요" |

---

### H. 계정·회원 관리

**정의:** 회원가입·탈퇴·로그인·회원정보 등 계정 자체에 관한 문의.

**제외 → 행선지**
- 회원 혜택 내용 → **G2**

| 중분류 | 정의 | 대표 발화 |
|---|---|---|
| **H1** 가입·탈퇴 | 가입·재가입·탈퇴 | "회원 탈퇴는 어떻게 하나요" · "회원가입을 하려고 하는데요 자꾸 이미 등록된 회원입니다 라는 메세지가" |
| **H2** 로그인·비밀번호 | 로그인 실패, 아이디·비번 분실 | "아이디하고 비밀번호를 몰라서요" · "비밀번호를 까먹었는데 어떻게 해야 하죠" |
| **H3** 회원정보 변경 | 정보·아이디 변경 | "회원 정보를 변경하라고 안내가 떠서요" · "회원정보를 변경하고 싶은데요" |

### I. 제품 A/S (고장·수리)

**정의:** 구매한 제품의 **고장·오작동**에 대한 수리 상담·접수. 품질·서비스망 문제.

**제외 → 행선지**
- 고장을 **새 상품 교환·반품**으로 해결하려는 경우 → **C1** (§4-② 규칙)
- 고장이 아닌 **사용법·관리** 문의 → **J1**
- 제품 구매 전 스펙 문의 → **D1**

| 중분류 | 정의 | 대표 발화 |
|---|---|---|
| **I1** IT기기 A/S·설정 | 휴대폰·PC·모니터·주변기기 고장·설정 | "휴대폰이랑 피씨를 연결 하려는데 안 돼서요" · "모니터에 화면이 안 나와요" |
| **I2** 생활가전 A/S | 세탁기·냉장고·에어컨·정수기·청소기 등 고장 | "탈수는 되는데 세탁할 때 소음이 나고" · "세탁기가 고장나가지구여 에이에스 좀 받을려구여" |
| **I3** TV A/S | TV 화면 이상·고장 | "티비가 잘 안나와서 화면이 좀 깨지고요 지지직 거려요" · "티비 에이에스 좀 받으려고 하거든요" |

> **자가조치 가능 여부(고객 스스로 해결 vs 기사 방문)는 이 단계에서 분류하지 않는다.** 증상별 판단에 도메인 지식이 필요하고 공개 데이터에는 없다. → **Recommendation 산출물로 전환:** *"증상별 자가조치 가능 여부 매뉴얼을 유관부서 협의로 제작"*.

---

### J. 제품 사용법·문의

**정의:** 고장이 아닌, 제품의 **사용법·관리·세척·재질·유통기한** 등 정보성 문의. 매뉴얼·FAQ로 해결 가능한 성격.

**제외 → 행선지**
- 고장·오작동으로 수리 필요 → **I**
- 제품 구매 전 스펙 문의(주문 동반) → **D1**

| 중분류 | 정의 | 대표 발화 |
|---|---|---|
| **J1** 제품 사용법·관리 | 사용·세척·보관·재질·유통기한·소모품 교체 | "용기 및 블레이드는 어떻게 관리하나요" · "물세탁 가능한가요 건조는 어떻게 하죠" · "클린커버의 교체 주기가 있나요" |

> **I(품질 문제)와 J(정보 제공 문제)는 원인·대응이 다르다.** I는 서비스망·부품·품질관리로, J는 매뉴얼·FAQ·상세페이지 개선으로 이어진다. 분할이 Root Cause·Recommendation의 정확도를 높인다.

---

### 기타

**정의:** 어느 대분류에도 속하지 않거나, 내용이 아니라 말투·문장구조로 묶인 발화.

**대표 발화:** "#@이름#입니다 #@주소#요 동의합니다 언제까지 통화해야 하나요" (신원확인·정보제공 동의만 있고 이슈 내용 없음)

`기타` 비율은 지표로 기록한다. 과다하면 택소노미에 빠진 유형이 있다는 신호다.

## 4. 경계 판정 규칙 (확정)

| # | 경계 | 확정 규칙 |
|---|---|---|
| ① | 배송 지연 ↔ 취소 | **요청이 무엇인가로 결정.** 기다리는 중 → A1 / 취소하겠다 → B2 |
| ② | 교환 ↔ A/S | **해결 수단으로 결정.** 새 상품 요구 → C1 / 수리 요구 → I |
| ③ | 주문 접수 ↔ 배송 지연 | D는 **신규 주문·변경으로 한정.** "주문했는데 안 와요" → A1 |
| ④ | 절차 문의 독립 유지 | E는 독립 대분류. **FAQ·사전공지로 해결됐어야 할 인입**이라 별도 집계 가치가 있음 |
| ⑤ | 결제 ↔ 환불 | "환불은 어떻게 받나요(카드결제)" → **C.** 질문 요지가 환불, 결제수단은 조건 |
| ⑥ | 혜택 ↔ 계정 | **혜택 내용 중심 → G / 가입·계정 행위 중심 → H** |
| ⑦ | A/S 품목 구분 | **품목별로 분리** (IT기기 / 생활가전 / TV). 자가조치 여부는 분류하지 않음 |
| ⑧ | 사유 불명 | 중분류를 **비워둔다.** 억지 배정 금지 |

## 5. 데이터 한계 (기록)

**주문 상태값을 활용할 수 없다.** 커머스는 `결제완료 → 상품준비중 → 배송중 → 배송완료` 상태를 가지며, 지연이 어느 단계에서 발생했는지에 따라 귀책이 달라진다(출고 전 지연 = 판매자 미조치 / 배송중 정체 = 택배사 지연 또는 운송장 오등록). 그러나 **고객이 상태값을 언급하는 비율은 10% 미만**이라 텍스트만으로는 분류할 수 없다.

→ **현업에서는 주문 DB와 조인하면 100% 확인 가능하다.** 이 한계는 Recommendation의 근거가 된다: *"VOC 분석은 주문 상태 데이터와 결합되어야 원인 규명이 가능하다."*

---

## 6. 현업 활용 및 재사용성

**본 구조는 이커머스 기본 구조를 따르며, 커머스의 업종별로 일부 대분류가 추가·삭제될 수 있다.**

- **범용 코어 (7):** 배송 / 취소 / 반품·교환·환불 / 절차·정책 / 결제 / 혜택·적립 / 계정·회원 — 업종 무관하게 적용된다.
- **업종 확장 (3):** `D 상품 주문 접수`는 전화 채널 특화, `I 제품 A/S`와 `J 제품 사용법`은 가전·내구재 특화다. 패션은 "사이즈·품질 이슈", 식품은 "신선도·유통기한 이슈" 등으로 대체된다.

현업에서는 이미 존재하는 문의 유형 코드체계(반품 사유 코드 등)를 뼈대로 삼고, 군집화는 "그 체계에서 빠진 새 유형"을 찾는 보정 용도로 쓰는 것이 일반적이다.

## 7. 확정 이력 및 검증 예정 사항

**① 대분류 I 분할 — 확정 (v1.1)**
제품 A/S·사용(25.8%)을 **I 제품 A/S(고장·수리, 17.2%)**와 **J 제품 사용법·문의(8.6%)**로 분할했다. 품질 문제와 정보 제공 문제는 원인·대응이 달라 별개 대분류가 타당하다. 다만 I가 여전히 17.2%로 F_score 상한(20%)에 근접하므로, Priority 랭킹에서 I의 하위(품목별 I1·I2·I3) 기여를 대시보드에서 함께 노출한다.

**② 중분류 경계 중 사유 판정이 어려운 쌍 (검증 시 확인)**
- B1(변심) ↔ B2(배송지연) — 취소 사유를 명시하지 않는 경우가 많음
- G1(쿠폰) ↔ G2(포인트) — 한 통화에 둘 다 등장하는 경우가 많음

→ §2-① null 허용 규칙으로 처리한다. 100건 라벨링(SPEC §12) 결과에서 이 쌍의 precision/recall을 확인해 Guideline을 보정한다.
