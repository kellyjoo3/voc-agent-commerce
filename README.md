# voc-agent-commerce

이커머스 고객센터(CS) VOC를 분석하는 **범용 지시문(Playbook) 기반** 도구.

Python 설치, API 키, 별도 과금 없이 동작한다.
당신이 이미 쓰는 LLM 구독(Claude Code, Codex CLI, Cursor 등)으로 실행한다.

---

# ▶ 실행 방법 (사용자용)

아래 블록을 **그대로 복사**해 당신이 쓰는 AI(Claude Code, Codex CLI, Cursor 등)에 붙여넣으세요.
`[내 파일]` 자리에 분석할 파일 경로만 바꾸면 됩니다.

```text
https://github.com/kellyjoo3/voc-agent-commerce 를 clone하고
PLAYBOOK.md를 따라 [내 파일] 을 분석해줘.

분석 대상은 위에 적은 [내 파일] 하나뿐이다.
리포 안의 examples/sample_voc_50.csv 는 형식 참고용이므로 분석하지 말 것.

시작 전 아래 3가지를 먼저 확인해서 보고할 것:
1. configs/commerce_cs.json 의 대분류 개수 (정답: 10개 + 기타)
2. configs/commerce_cs.json 의 playbook.actions 개수 (정답: 28개)
3. scripts/priority_calc.py 를 실제로 실행할 수 있는 환경인지

진행 중 반드시 지킬 것:
- 택소노미는 A~J + 기타만 사용. 새 분류 체계를 만들지 말 것
- F_score = min(비중% / 20, 1) × 100  ← 20%가 상한
  · 최대값 대비 상대비율이 아님
  · 비중 24% → 100,  13% → 65,  9% → 45
- Priority 는 priority_calc.py 를 실행해서 계산하고 출력 원문을 인용할 것
  · 실행할 수 없으면 "미실행"이라고 리포트에 명시하고 위 공식으로 계산
  · 절대 자기만의 다른 공식을 쓰지 말 것
- 등급은 P1 = 상위 3개 AND Priority >= 50. 심각하다는 이유로 올리지 말 것
- 리포트는 templates/report_template.html 파일을 읽어서
  "/*__REPORT_DATA__*/ null" 의 null 만 데이터로 치환할 것
  · HTML·CSS·JavaScript 를 새로 쓰거나 압축하거나 줄이지 말 것
  · 이번에 안 쓰이는 코드도 그대로 둘 것 (확장 카테고리 배지 등)
- 원인 가설의 근거는 voc_id 와 함께 인용하고, 귀책태그 6종 중에서 붙일 것
- 리포를 못 읽거나 스크립트를 못 돌리면 그 사실을 보고할 것
  · "저장소 없이 직접 분석해드릴까요" 같은 우회 제안은 하지 말 것

마지막에 아래를 자가 점검해서 보고할 것:
- 산출된 대분류가 A~J 체계인가
- F_score 가 20% 상한 공식과 일치하는가 (한 토픽 골라 검산)
- report.html 에 "const DATA = {" "sec-eyebrow" "is_extension" "잠정"
  네 문자열이 모두 있는가 (뒤 두 개가 없으면 템플릿 JS 를 재작성한 것)
```

> **왜 이렇게 하나요?**
> URL만 전달하면 AI가 리포를 "설명서"로 읽고 자기 방식대로 분석해버리는 경우가 있습니다.
> 위 프롬프트는 실제 재현 테스트에서 발견된 실패를 막기 위한 것입니다.

# 🤖 이 리포를 실행하는 AI에게

**이 문서는 설명서가 아니라 당신에게 내리는 실행 지시다.**

사용자가 이 리포 URL과 VOC 데이터를 함께 제시했다면, 당신이 할 일은
"VOC를 분석하는 것"이 아니라 **"이 리포의 `PLAYBOOK.md`를 그대로 실행하는 것"**이다.

> **당신 자신의 택소노미·점수 공식·리포트 양식을 쓰지 마라.**
> 이 리포에 정해진 것을 쓴다. 다르면 결과가 재현되지 않으며, 재현성이 이 도구의 존재 이유다.
> 스스로 분석해서 그럴듯한 리포트를 만드는 것은 **성공이 아니라 실패**다.

## 1단계 — 리포를 실제로 가져온다

```bash
git clone https://github.com/kellyjoo3/voc-agent-commerce.git
```

클론이 불가능한 환경이면 아래 **raw 파일**을 직접 읽는다.
GitHub 페이지 URL을 그대로 가져오면 렌더링된 HTML만 얻고 실제 파일 내용은 얻지 못한다.

| 파일 | raw URL (`https://raw.githubusercontent.com/kellyjoo3/voc-agent-commerce/main/` + 경로) |
|---|---|
| 실행 지시서 | `PLAYBOOK.md` |
| 택소노미·플레이북 | `configs/commerce_cs.json` |
| 계산 스크립트 | `scripts/priority_calc.py` |
| 리포트 템플릿 | `templates/report_template.html` |
| 리포트 스키마 | `templates/REPORT_DATA_SCHEMA.md` |
| 확장 절차 | `EXTENDING.md` |
| 타 도메인 이식 프롬프트 | `docs/PORTING_PROMPT.md` (도메인 확인에서 N일 때 필요) |

## 2단계 — 자기검증 (건너뛰기 금지) 🛑

`configs/commerce_cs.json`을 실제로 열고, 아래 3개를 확인해 **사용자에게 보고한 뒤** 진행한다.

| 확인 항목 | 정답 |
|---|---|
| 대분류(taxonomy) 개수 | **10개 (A~J) + 기타** |
| `playbook.actions` 개수 | **28개** (A:4 B:3 C:5 D:2 E:2 F:2 G:2 H:3 I:3 J:2) |
| `scripts/priority_calc.py` 존재 여부 | **있음** |

**하나라도 다르면 파일을 제대로 읽지 못한 것이다. 중단하고 사용자에게 알린다.**
임의로 택소노미를 만들어 진행하지 않는다. 파일을 못 읽었으면 "못 읽었다"고 보고하는 것이
잘못된 결과를 내놓는 것보다 낫다.

## 3단계 — 분석 대상·도메인 확인 🛑

분석을 시작하기 전에 아래를 **한 번에 묻고 답을 받은 뒤** 진행한다.

```
분석 대상: [파일 경로]

이 도구는 커머스 CS(이커머스 고객센터) VOC 전용입니다.
택소노미·귀책태그·실행안이 모두 커머스 기준으로 고정되어 있습니다.
분석하려는 데이터가 커머스 CS VOC가 맞습니까? [Y/N]
```

**Y이면** 4단계로 넘어가 평소대로 진행한다. 추가로 할 일은 없다.

**N이면 분석을 진행하지 마라.** 다른 도메인(은행·병원·통신·보험·공공 등) 데이터를
커머스 택소노미로 분류하면 대부분 "기타"로 몰리거나 잘못 배정되어
Priority와 원인 가설이 전부 무의미해진다. 대신 아래 4가지를 수행한다:

1. 커머스 CS 전용이라 해당 데이터는 분석할 수 없다고 알린다.
2. **준비물을 안내한다** — VOC 300건 이상 / 조직 문서 2종 이상
   (응대 매뉴얼·팀 R&R·이슈트래커 export·지표 정의서 중) / 담당자 확인 시간 2~3시간.
   조직 문서가 없어도 우선순위 산출까지는 가능하며 실행안은 검토 시트로 대체된다는 점도 함께 알린다.
3. **[`docs/PORTING_PROMPT.md`](docs/PORTING_PROMPT.md)의 "복사용 프롬프트" 블록을 출력한다.**
   파일 경로만 알려주지 마라 — 사용자는 그 파일을 열 수단이 없을 수 있다.

   > ⚠️ **파일 내용을 그대로 복사하라. 다시 쓰지 마라.**
   > 번역하지 마라(한국어 원문 그대로) · 요약·축약하지 마라 · 섹션을 빼지 마라.
   > 채워도 되는 것은 `[ ]` 안의 값뿐이다(도메인명·데이터 경로·조직문서 경로).

   출력 후 아래가 **모두** 포함됐는지 확인해 보고한다. 하나라도 없으면
   원문을 다시 읽어 그대로 출력하라.

   | 확인 문자열 | 없으면 |
   |---|---|
   | `## 진행 방식` | 5단계 절차가 통째로 빠졌다 |
   | `5단계 — 회귀 확인` | 마지막 단계가 잘렸다 |
   | `## 금지` | 금지 사항이 빠졌다 |
   | `새로 만들어야 하는 것` | 작성 대상 목록이 빠졌다 |
4. **새 세션에서 실행하라고 안내한다.** 이 세션에는 커머스 설정이 로드되어 있어
   그대로 이어가면 결과가 섞인다.

**위 4가지만 하라. 다른 선택지를 만들지 마라.** 실제 실행에서 아래와 같은
제안이 나온 사례가 있으며, 셋 다 금지된 행동이다:

| 실제로 나왔던 제안 | 왜 금지인가 |
|---|---|
| "저장소 없이 제가 직접 분석해드릴까요" | 도구를 우회한다. 재현성이 사라진다 |
| "`commerce_cs.json`의 택소노미를 해당 도메인 카테고리로 교체하면 됩니다" | `docs/PORTING_PROMPT.md`가 명시적으로 금지한다 — 이름만 바꾸는 것이 아니라 그 도메인 VOC에서 다시 도출해야 한다 |
| "요약 데이터로 간단한 Priority 리포트는 만들 수 있습니다" | 감정·원인 근거 없이 산출한 Priority는 이 도구의 결과가 아니다 |

**파일을 지정하지 않았다면 그것도 함께 묻는다.**
이 리포의 `examples/sample_voc_50.csv`는 **형식 참고용 합성 데이터**이므로,
리포에 CSV가 하나뿐이라는 이유로 기본 분석 대상으로 삼지 마라.

## ⚠️ 가장 자주 어기는 두 지점 — 여기만은 반드시 지켜라

PLAYBOOK 09·12단계에 상세 규정이 있으나, 문서를 끝까지 읽지 않고 건너뛰는 사례가
반복 관측되어 핵심을 여기로 옮겨둔다.

### 09단계 — F_score 는 20% 상한 공식이다

```
F_score = min(비중% / 20, 1) × 100
```

**20%가 만점선(cap)이다. 최대값 대비 상대비율이 아니다.**

| 비중 | 올바른 F_score | 흔한 오답(상대비율) |
|---|---|---|
| 58% | **100** (상한) | 100 |
| 24% | **100** (상한) | 41 |
| 13% | **65** | 22 |
| 9% | **45** | 16 |
| 3% | **15** | 5 |

토픽 하나를 골라 위 공식으로 검산하라. 값이 다르면 잘못 계산한 것이다.

**스크립트를 실행할 수 없는 환경이라면** — 클론이 안 됐거나, Python·pandas·openpyxl이
없거나, 입력이 xlsx인 경우 등:

1. **자기만의 공식을 만들지 마라.** 위 공식을 그대로 손으로 적용한다.
2. 리포트와 사용자 보고에 **"`priority_calc.py` 미실행 — 수기 계산"**을 명시한다.
3. 숨기고 진행하는 것이 가장 나쁘다. 실행 여부를 밝히면 사용자가 판단할 수 있다.

S_score 배점도 함께 기억하라: **Positive 0 · Neutral 1 · Negative 3 · Severe Negative 5**.
`S_score = (감정 평균 / 5) × 100`. 등급은 `P1 = 상위 3개 AND Priority ≥ 50`이며,
Priority는 **0~100 스케일**이다.

### 12단계 — 리포트 HTML을 새로 작성하지 마라

**템플릿 파일을 읽어 문자열 하나만 바꾼 결과를 저장한다.**
`/*__REPORT_DATA__*/ null` 에서 `null`을 데이터 JSON으로 치환하는 것이 전부다.

> **CSS·JavaScript를 다시 쓰지 마라.** 보기에 같아 보이도록 재작성하거나, 짧게
> 압축하거나, 필요 없어 보이는 코드를 빼지 마라. 템플릿 JS에는 이번 데이터에
> 안 쓰이더라도 반드시 남아 있어야 하는 처리가 들어 있다 — 확장 카테고리 배지,
> 잠정(draft) 표기, 확장 안내 박스 등이다. 이것들을 빼면 다음 실행에서
> **근거가 부족한 카테고리가 확정된 것처럼 보인다.**

완료 후 `output/report.html`에서 아래 6개 문자열을 확인해 사용자에게 보고한다.

| 확인 문자열 | 없으면 |
|---|---|
| `const DATA = {` | 치환 실패 |
| `sec-eyebrow` | 템플릿 미사용 |
| `dist-track` | 템플릿 미사용 |
| `print-single` | 템플릿 미사용 |
| `is_extension` | **JS를 재작성함** — 확장 카테고리 배지가 사라졌다 |
| `잠정` | **JS를 재작성함** — draft 표기가 사라졌다 |

마지막 두 개가 없으면 파일을 읽어 치환한 것이 아니라 **새로 쓴 것**이다.
템플릿을 다시 읽어 치환부터 하라.

직접 작성하면 **잠정(draft) 배지 · "Priority ≠ 실행순서" 경고 · F/S/T 기여분 분해 ·
추세 산출 불가 경고 · 검증 이행 내역 · 산출물별 PDF 출력**이 전부 사라진다.
보기 좋은 HTML을 만드는 것이 목적이 아니라, **이 안전장치들을 전달하는 것**이 목적이다.

## 절대 금지

| ❌ 금지 | 이유 |
|---|---|
| **이 도구를 우회한 대체 분석 제안** | "저장소 없이 제가 직접 분석해드릴까요", "간단히 정리해드릴까요" 같은 제안을 **하지 마라.** 그 제안은 이 도구의 존재 이유(재현성·검증가능성)를 무효화한다. 실행할 수 없으면 **"실행할 수 없다"고 보고하라.** 대신 해줄 것을 만들어내지 마라 |
| **임의 선택지 생성** | 상황이 애매할 때 A/B/C 같은 대안을 스스로 만들지 마라. 이 문서와 `PLAYBOOK.md`에 정해진 분기만 따른다 |
| 자체 택소노미 생성 (A~J 외 분류 체계) | 실행마다 결과가 달라져 재현성이 사라진다 |
| Priority 암산 | 반드시 `scripts/priority_calc.py`를 실행하고 **출력 원문을 인용**한다. F_score는 `min(비중%/20, 1) × 100` (20% 상한)이며 최대값 대비 상대비율이 아니다 |
| 리포트 HTML 직접 작성 | `templates/report_template.html`의 `/*__REPORT_DATA__*/ null`을 치환하는 방식만 사용한다 |
| 등급 임의 조정 | `P1 = 상위 3개 AND Priority ≥ 50`. 심각도가 높다는 이유로 상향하지 않는다 |
| voc_id 없는 근거 인용 | 원인 가설의 근거는 **voc_id와 함께** 인용한다. 검증 불가능한 인용은 무효다 |
| 귀책태그 생략 | `[판매자] [택배사] [플랫폼/시스템] [고객] [정보/매뉴얼] [?불명]` 6종에서 선택한다 |

## 자주 발생하는 실패

실제 재현 테스트에서 **두 차례 관측된** 사례다. 같은 실수를 반복하지 마라.

**1차 테스트**

  **자신이 규칙을 어겼다는 사실 자체를 인지하지 못했다.** 반드시 위 검산표와 대조하라
- 템플릿 마커 4종 전부 부재 — 12단계 게이트를 확인하지 않음

## 동작 원리

이 리포에는 실행 파일이 없다. 대신 [`PLAYBOOK.md`](PLAYBOOK.md)라는 상세 지시문이 있다.

```
당신의 CSV  +  이 리포 URL  →  당신이 쓰는 AI에게 전달
                                   ↓
                          AI가 PLAYBOOK.md를 읽고
                          VOC 분석 파이프라인을 직접 수행
                                   ↓
                         output/ 에 분석 결과 저장
```

**의미 판단**(Topic·Sentiment 분류, 원인 가설)은 AI가 직접 수행한다.
**계산**(F/S/T·Priority)은 `scripts/priority_calc.py`를 실행해서 처리한다.
**사람 검토 지점**에서는 AI가 실제로 멈추고 사용자 확인을 받는다.

## 빠른 시작

1. **이 리포를 클론 또는 URL 공유**

   ```bash
   git clone https://github.com/<your-username>/voc-agent-commerce.git
   ```

   또는 GitHub URL(`https://github.com/<your-username>/voc-agent-commerce`)을 그대로 AI에게 전달한다.

2. **당신의 LLM 환경에서 아래 메시지를 입력한다**

   ```
   이 리포의 PLAYBOOK.md를 읽고, 내 CSV 파일을 분석해줘.
   CSV 경로: [당신의 CSV 파일 경로]
   ```

3. **AI가 00단계부터 시작한다**
   - 컬럼 매핑을 제안하고 확인을 요청
   - 분류 → 계산 → 원인 가설 → 실행안 순으로 진행
   - 사람 검토가 필요한 지점에서 멈추고 질문

## 분석 택소노미 (A~J)

원본 이커머스 CS 데이터 15,163건의 임베딩·군집화를 거쳐 사람이 확정한 10개 대분류:

| 대분류 | 이름 |
|---|---|
| A | 배송 지연·미도착 |
| B | 주문 취소 (배송 전) |
| C | 반품·교환·환불 (배송 후) |
| D | 상품 주문 접수 |
| E | 절차·정책 문의 |
| F | 결제 방법·오류 |
| G | 혜택·적립 |
| H | 계정·회원 관리 |
| I | 제품 A/S (고장·수리) |
| J | 제품 사용법·문의 |

상세 정의·포함·제외(행선지) Guideline은 [`configs/commerce_cs.json`](configs/commerce_cs.json) 참조.
원본 문서는 [`context/topic_taxonomy.md`](context/topic_taxonomy.md).

## 택소노미 확장

"기타" 비율이 15%를 초과하면 PLAYBOOK이 **확장 마법사**를 자동 실행한다.
새 카테고리는 [`EXTENDING.md`](EXTENDING.md)의 체크리스트 6개 필드를 모두 채운 후
[`configs/local_extensions.json`](configs/local_extensions.json)에 저장된다.

`configs/commerce_cs.json`(원본)은 수정되지 않는다.
확장 마법사는 필드를 한 번에 하나씩, 매 필드 사용자 확인 후 진행한다.

## Priority 공식

```
Priority = 0.4 × F_score + 0.4 × S_score + 0.2 × T_score
```

| 지표 | 정의 | 범위 |
|---|---|---|
| F_score | Frequency (빈도). 상한 20% 적용 | 0~100 |
| S_score | Severity (심각도). Sentiment 평균 기반 | 0~100 |
| T_score | Trend (추세). 직전·최근 기간 비중 변화율 | 0~100 |

**Priority는 실행 순서가 아니다.** 심각도(S)가 높지만 빈도(F)가 낮은 이슈는 Priority는 낮아도 별도 원인 분석이 필요할 수 있다.

## 한계 사항

- 이 택소노미는 한국 이커머스 콜센터 데이터 기반이다. 패션·식품 특화 유형(사이즈 문의, 신선도 등)은 기본 포함되지 않으며, 확장 마법사로 추가할 수 있다.
- Trend 계산은 `created_at`이 있을 때만 동작한다. 합성 타임스탬프를 사용한 경우 Trend 수치는 실측이 아니다.
- Priority 수식에 Business Impact(매출·이탈 영향)는 포함되지 않는다. VOC 분석의 책임 범위를 정확히 그었기 때문이다 (SPEC §1-A). 사업 데이터 확보 시 `0.3F+0.3S+0.2T+0.2B`로 확장 가능하다.
- 원인 규명은 주문 DB·택배 API 데이터와의 결합이 있어야 정확하다. 텍스트만으로는 가설 수준이다.
- **이 도구는 커머스 CS 전용이다.** 은행·병원·통신 등 다른 도메인으로 이식하려면
  조직 고유의 실행 지식(Action Playbook·Metric Dictionary)이 필요하며,
  이는 VOC 데이터에서 도출할 수 없다. 어디가 막히고 무엇을 설정해야 하는지는
  [`docs/PORTING_TO_OTHER_DOMAINS.md`](docs/PORTING_TO_OTHER_DOMAINS.md)에 설계 문서로 정리했다.
  실제 착수 시 쓸 프롬프트는 [`docs/PORTING_PROMPT.md`](docs/PORTING_PROMPT.md)에 있다.
  (설계만 완료, 미구현 — 실제 조직 문서로 검증할 수 없어 구현을 보류했다)
  **`docs/`는 설계 기록이며 커머스 실행에 사용하지 않는다.**
