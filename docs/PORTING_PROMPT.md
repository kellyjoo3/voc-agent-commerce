# 다른 도메인 이식 — 착수 프롬프트

> ## ⛔ 커머스 VOC 분석을 실행 중인 AI에게
>
> **이 문서는 실행에 사용하지 않는다.** 지금 읽고 있다면 덮고 `PLAYBOOK.md`로 돌아가라.
> 이 문서는 *새로운 도메인용 config를 만들 때* 사람이 복사해 쓰는 프롬프트다.
> 커머스 실행 중에 이 절차를 시작하면 안 된다.

---

이 문서는 `voc-agent-commerce`를 다른 도메인(은행·병원·통신·공공 등)으로 이식할 때
**새 세션 첫 프롬프트로 복사해 쓸 문안**이다.
설계 근거는 [`PORTING_TO_OTHER_DOMAINS.md`](PORTING_TO_OTHER_DOMAINS.md)에 있다.

---

## 시작 전 준비물

아래를 갖추지 못했다면 **아직 시작하지 마라.** 준비 없이 시작하면
AI가 조직 지식을 지어내고, 그 결과는 검증할 수 없다.

| # | 준비물 | 없으면 |
|---|---|---|
| 1 | **VOC 원본 데이터** (최소 300건, 1,000건 이상 권장) | 택소노미 초안을 뽑을 수 없다 |
| 2 | **조직 문서 2종 이상** — 응대 매뉴얼 / 팀 R&R / 이슈트래커 export / 지표 정의서 중 | Action Playbook·Metric을 만들 수 없다 → 축소 모드로만 가능 |
| 3 | **도메인 담당자 확인 시간** — 최소 2~3시간 | 택소노미·귀책 확정을 사람이 해야 한다 |

**2번이 없어도 진행은 가능하다.** 다만 11단계(실행안)가 검토 시트로 대체되고,
산출물은 "우선순위 + 원인 가설"까지가 된다. 이것도 충분히 유효한 결과다.

## 지켜야 할 것

절대 바꾸지 마라 (도메인이 달라도 고정):
- Sentiment 4단계 배점: Positive 0 / Neutral 1 / Negative 3 / Severe Negative 5
- Priority = 0.4×F + 0.4×S + 0.2×T
- F_score = min(비중% / 20, 1) × 100   ← 20% 상한
- P1 = 상위 3개 AND Priority >= 50
- scripts/priority_calc.py 는 그대로 재사용

새로 만들어야 하는 것:
- taxonomy (대분류·중분류) + guideline (정의·포함·제외+행선지)
- filters.exclude_keywords (도메인 밖 문의 격리 패턴)
- cause_tags (귀책 주체)
- playbook.actions (조직이 실제로 취할 수 있는 조치)
- metrics (측정 가능한 지표)

## 진행 방식

1단계 — 택소노미 초안
  내 VOC 에서 200~300건을 표본으로 읽고 반복 패턴을 군집화해
  대분류 후보를 제안해라. 아직 확정하지 마라.

2단계 — 택소노미 확정 (한 번에 하나씩)
  후보마다 EXTENDING.md 의 6개 필드를 한 필드씩 물어라.
  · 정의 / 포함 예시(실제 voc_id 인용 2건 이상) / 제외+행선지
  · 귀책태그 / Action / Metric
  매 필드마다 내 확인을 받고 다음으로 넘어가라.
  실제 발화 근거가 2건 미만이면 확정하지 말고 draft 로 표시해라.

3단계 — 조직 문서에서 Action·Metric 도출
  조직 문서를 제공했다면 거기서 도출해라.
  · 출처를 항목마다 명시해라 (어느 문서 몇 쪽/어느 행)
  · 문서에 없는 내용을 추론으로 채우지 마라
  조직 문서가 없다면 이 단계를 건너뛰고, 11단계는 검토 시트로
  대체한다고 config 에 명시해라.

4단계 — config 생성 + 대조표
  configs/[도메인].json 을 만들고,
  각 항목이 어디서 왔는지 대조표를 제출해라
  (VOC 데이터 / 조직 문서 이름+위치 / 내가 직접 확정 / 커머스에서 그대로 승계)

5단계 — 회귀 확인
  커머스 config 를 새 스키마로 읽었을 때 기존 결과가 그대로 나오는지 확인해라.
  달라지면 스키마 일반화가 잘못된 것이다.

- 커머스의 A~J 택소노미를 그대로 가져다 이름만 바꾸지 마라.
  내 VOC 데이터에서 다시 도출해야 한다
- Sentiment 배점·Priority 공식·F_score 상한을 바꾸지 마라
- 한 번에 여러 필드를 채워서 제안하지 마라. 한 필드씩 확인받아라

## 완료 판정 기준

새 도메인 config 가 완성되었는지는 아래로 판정한다.

- [ ] 대분류마다 정의·포함·제외(행선지 포함)가 모두 채워졌는가
- [ ] 포함 예시가 **실제 VOC 원문 인용**인가 (지어낸 문장이 아닌가)
- [ ] 귀책태그가 그 도메인의 실제 책임 주체인가
- [ ] Action 마다 **출처 문서**가 명시되었는가 (없으면 `[내부 확인 필요]`)
- [ ] Metric 이 그 조직에서 **실제로 측정 중인 지표**인가
- [ ] Sentiment 배점·Priority 공식·F_score 상한이 커머스와 동일한가
- [ ] 커머스 config 로 회귀 확인 시 기존 결과가 재현되는가

**마지막 두 항목이 가장 중요하다.** 고정 항목이 바뀌면 도메인 간 결과 비교가
불가능해지고, 커머스 회귀가 깨지면 스키마 일반화가 잘못된 것이다.
