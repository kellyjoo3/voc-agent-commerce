# Cause Taxonomy (v1.0)

> **본 문서는 이커머스 CS 일반 참조 모델(Reference Model)이며, 특정 기업의 실제 원인 체계가 아니다.**
> 각 원인은 VOC에서 **관찰된 패턴을 근거로 한 가설**이다. 확정된 사실이 아니다.

## 작성 원칙

| # | 원칙 | 적용 |
|---|---|---|
| 1 | 관찰 근거 표기 | 원인마다 대표 voc_id. 근거 없는 원인은 넣지 않음 |
| 2 | 참조 모델 선언 | 상단 고지 |
| 3 | **Topic ≠ Cause** | Topic(무엇이 발생)과 별개로, 여기서는 **왜 발생했는가**의 가설만 |
| 4 | 데이터 한계 명시 | 귀책 판별 불가 부분 표시 |
| 5 | 2계층 정합 | 대분류 A~J 기준. 각 원인에 **귀책 주체** 태그 |

**귀책 주체 태그:** `[판매자]` `[택배사]` `[플랫폼/시스템]` `[고객]` `[정보/매뉴얼]` `[?불명]`

> **사용법 (Root Cause 단계):** LLM은 이 목록에서 원인을 **선택·조합**하고, 각 가설에 실제 voc_id를 인용한다. 목록에 없는 원인을 지어내지 않는다. 인용 검증은 코드가 수행한다(SPEC §9).

## 원인 → 귀책 요약 (개선 방향 도출용)

| 귀책 주체 | 주요 원인 | 개선 축 |
|---|---|---|
| `[판매자]` | 출고 지연, 하자, 오배송 | 출고 SLA, 품질관리, 검수 |
| `[택배사]` | 배송 정체, 파손, 완료 오처리 | 택배사 관리·평가, 파손 보상 |
| `[플랫폼/시스템]` | 회수·환불 지연, 결제 오류, 취소 미반영 | 내부 프로세스·시스템 안정성 |
| `[정보/매뉴얼]` | 절차 문의, 사용법, 혜택 안내 | FAQ·상세페이지·매뉴얼 (셀프서비스) |
| `[고객]` | 변심, 오주문 | 상세정보 강화로 사전 예방 |

> **데이터 한계 종합:** 귀책 주체 판별은 텍스트만으로 부분적이다. 정확한 원인 규명은 주문 DB·택배 API·품질 데이터와의 결합이 필요하며, 이는 본 MVP 범위 밖이다. 본 문서의 원인은 **개선 우선순위 판단을 돕는 가설**로 사용한다.
