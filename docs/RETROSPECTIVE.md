## 1. 단계별 회고

| 단계 | 핵심 결정 | 배운 것 |
|---|---|---|
| **① 최초 설계**<br>방법론 데모 | 역할을 셋으로 분리 — **의미 판단은 AI, 계산은 Code, 기준·검토·결정은 Human.** Business Impact를 Priority에서 뺀 것도 "데이터가 없어서"가 아니라 **부서 경계**라는 역할 근거로 못박음 | 자기일관성 76.7%를 한동안 "정확도"로 불렀다. 블라인드 정답지가 없다는 지적을 받고서야 정정.<br>**무엇을 재는지 정의하지 않으면 숫자가 스스로 거짓말한다** |
| **② 도구화**<br>Playbook 방식 | API 키·설치가 필요한 CLI 대신 **지시문을 호스트 AI가 읽고 수행**하는 방식. 사용자가 이미 쓰는 LLM 구독으로 동작 | 이관 목록만 넘기고 **원본 파일을 안 넘겼다.** 그 세션은 택소노미를 요약문에서 재구성하고 "원본 인용"이라 표기.<br>**없는 것을 베낄 수는 없다. 인계는 목록이 아니라 파일이어야 한다** |
| **③ 재현성 개선**<br>가장 길었던 구간 | 제3자 재현 5회 테스트. **매번 다른 항목이 실패** | 아래 별도 서술 |
| **④ core**<br>범용 엔진 | **만들지 않기로 결정.** Action Playbook은 VOC에서 도출도 일반화도 불가능한 조직 내부 지식이라, 실제 문서 없이 만들면 검증할 수 없다 | 검증 수단 없는 구현은 **내내 싸운 "근거 없는 생성"을 설계 층위에서 반복하는 것**.<br>만들지 않기로 한 판단과 근거를 남기는 것도 산출물이다 |
| **⑤ 최종** | 복사 프롬프트 경로로 전수 검산 통과 — 분류·점수·등급·템플릿 전 항목 일치 | 남은 한계: 프롬프트 경로 **표본 1회**, 확장 마법사 미검증 |

### ③ 재현성 개선 — 상세

| 회차 | 택소노미 | 스크립트 | 템플릿 |
|---|---|---|---|
| 1차 | ✗ | ✗ | ✗ |
| 2차 | ✓ | ✗ | ✗ |
| 3차 | ✓ | ✓ | ✓ |
| 4차 | ✗ | ✗ | ✗ |

- 실패를 볼 때마다 지시를 추가했다. **9회 연속 추가**했고 문서는 766행 → 1,245행이 됐지만 준수율은 오르지 않았다.
- 원인을 **세 번 단정했고 세 번 다 데이터에 무너졌다.** 프레이밍 오염(→ 통과 회차에도 같은 구조), 문서 희석(→ 가장 짧던 183행이 최악), config 채굴(→ 읽은 파일 특정 불가).
- 답은 새로 만든 것이 아니라 **만들어두고 한 번도 쓰지 않은 것**이었다. 복사용 프롬프트를 처음 시험하자 전 항목 통과. **URL만 전달 4회 중 1회 / 프롬프트 사용 1회 중 1회.**

## 2. KPT

**Keep**
- **기준을 데이터 보기 전에 선언하고 사후 조정하지 않기.** 결과를 방어 가능하게 만든 유일한 장치.
- **판단·계산·결정의 분리.** 점수를 코드만 계산하게 한 덕분에 "AI가 암산했다"를 기계적으로 잡아냈다.
- **눈으로 믿지 않고 전수 검산하기.** 리포트가 자기 검증표에 "통과"로 적어둔 항목이 실제로는 위반이던 사례가 두 번.

**Problem**
- **커밋이 논의보다 앞선 적이 있다.** 방향 합의 전에 변경이 들어가면 되돌리는 비용이 생기고 추적이 흐려진다.
- **중간점검이 없었다.** 실패에 반응했을 뿐, "지금 이게 원래 목표에 맞나"를 주기적으로 되묻지 않았다.
- **원인 단정 → 즉시 수정**을 반복했다. 세 번 틀렸다.
- **만들어놓고 검증하지 않은 자산을 방치했다.** 답이 거기 있었는데 5회 내내 쓰지 않았다.

**Try**
1. **커밋 전 합의 절차 고정** — 변경 범위·이유·영향을 먼저 정리해 확인받고 실행한다. 자동 진행 금지.
2. **중간점검 체크포인트** — 구간마다 *"왜 하는가 / 뼈대대로 가는가"*를 원래 문서와 대조한다. 방향 검증 없이 개선만 쌓으면 회귀한다.
3. **변수는 하나씩** — 원인이 불확실하면 확신도를 밝히고, 근거가 가장 강한 하나만 건드린다.
4. **새 장치는 만든 즉시 1회 검증** — 검증 안 된 장치는 없는 것과 같다.
5. **추가가 답이 아닐 수 있음을 먼저 의심** — 9번 추가해도 안 되면 방식 자체를 바꿔야 한다.

---

**한 줄 요약 —** 설계는 초반에 단단했고, 무너진 곳은 전부 **원본을 넘기지 않았거나, 검증하지 않았거나, 근거 없이 단정한** 지점이었다.
